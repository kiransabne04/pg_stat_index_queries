# AGENTS.md — instructions for coding agents (Codex, Claude Code, others)

Read this file fully before changing anything. It is the single source of truth for how to build, test and change this repository.

## What this repo is

Two PostgreSQL extensions that answer "which queries use this index?":

- `pg_stat_index_queries` (root directory, C): executor hooks walk every executed plan and count (database, index, queryid, toplevel) in shared memory. Self-hosted Postgres 15–18.
- `pg_index_deps` (`sql_edition/`, pure SQL/PL/pgSQL): parses index names out of captured plan text (`aurora_stat_plans`, `pg_stat_plans`) and runs a HypoPG drop-impact check. Runs on RDS and Aurora too.

Product context and requirements: `docs/PRD-and-Spec.md`. Design: `docs/ARCHITECTURE.md`. Decisions already made: `docs/DECISIONS.md` (don't reopen them without saying so).

## Commands

Run tests as a **non-root** user (Postgres refuses to start as root).

```bash
make                                    # build native extension
sudo make install                       # install into the pg_config in PATH
make installcheck                       # native regression + TAP tests (starts its own temp server)
make -C sql_edition install installcheck  # SQL edition (needs pg_stat_plans and HypoPG installed)
make -C sql_edition managed             # regenerate install.sql and install_pg_tle.sql
make test-all                           # everything
make PG_CONFIG=/usr/lib/postgresql/17/bin/pg_config ...   # target another version
./bench/run.sh                          # overhead benchmark (minutes; not part of tests)
```

Prerequisites (Debian/Ubuntu): `postgresql-server-dev-NN`, `libipc-run-perl` (TAP), `postgresql-NN-hypopg`, and pg_stat_plans built from https://github.com/pganalyze/pg_stat_plans for the SQL edition tests.

## Rules

1. **Never weaken or delete a test to make it pass.** If expected output must change, explain why in the commit message and confirm the new output is correct by reading it.
2. Expected files (`expected/*.out`) are generated by running the tests, then **reviewed line by line**. Never hand-edit them to match.
3. Keep PostgreSQL 15–18 compatibility. Version-specific code goes behind `#if PG_VERSION_NUM >= …`. Check signatures in each version's headers (e.g. `ExecutorRun_hook_type` lost `execute_once` in 18).
4. Follow PostgreSQL C style: tabs, BSD braces, `palloc`, `ereport`, no C99 declarations after statements (`-Wdeclaration-after-statement` is on). Build must be warning-free.
5. The extension must **never error a user's query**. If tracking fails, skip it for that statement.
6. Read-only: nothing in this repo writes to user tables, drops indexes or executes user queries. `index_drop_impact` only runs EXPLAIN and must always unhide indexes, including on error paths.
7. SQL changes: new objects go in a new version script (`--0.2--0.3.sql`) plus the full script for the new version; bump `default_version`; add an upgrade test.
8. Regenerate `sql_edition/install.sql` and `install_pg_tle.sql` with `make -C sql_edition managed` after changing the SQL edition. Never edit the generated files.
9. Update `CHANGELOG.md` and the relevant doc in `docs/` in the same change.
10. No employer, client or real production data, schemas or numbers anywhere, ever. Synthetic data only.
11. No network access needed for builds or tests other than package installs.

## Definition of done

- `make` builds with no warnings.
- `make installcheck` and `make -C sql_edition installcheck` pass.
- New behaviour has a test (regression or TAP).
- Docs and CHANGELOG updated.
- For performance-sensitive changes: `./bench/run.sh` before/after numbers in the PR description.
