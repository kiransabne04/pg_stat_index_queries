# Decisions

| Date | Decision | Why |
|---|---|---|
| 2026-10-15 | Store no query text; join pg_stat_statements on queryid | Avoids a second text store and its memory cost |
| 2026-10-15 | Skip catalog indexes by default | Catalog lookups would drown out user indexes |
| 2026-10-15 | `EXECUTE`/`PREPARE` don't count as nesting | Same as pg_stat_statements; prepared statements are the user's top-level statements |
| 2026-10-21 | Persist at clean shutdown only; delete file after load | Same model as pg_stat_statements; a crash must never reload stale counters |
| 2026-10-27 | **Reopens 2026-10-21:** native 0.9.1 also saves every `save_interval` (default 300 s) from a background worker, keeps the file after loading, and reloads it after a crash (T09) | A long tracking window is what makes "no recorded use" believable, and one crash or OOM kill wiped it. A snapshot at most 5 minutes old is not stale in the sense that mattered (counts from before a reset): a reset removes the file and a save racing it is discarded. `save_interval = 0` keeps the old model. Library-only change, so 0.9.1 with no SQL version bump |
| 2026-10-21 | Partition roll-up reports max per partition as calls, sum as partition scans | One statement can scan many partitions; summing would overcount statements |
| 2026-10-21 | SQL edition is a separate extension (`pg_index_deps`) in the same repo | Must install on RDS/Aurora without C; shares docs and tests with the native extension |
| 2026-10-21 | Drop-impact uses HypoPG hide + EXPLAIN (GENERIC_PLAN) | Works on managed Postgres; never executes queries or drops anything |
| 2026-10-21 | Same index name in two schemas is flagged `ambiguous`, not guessed | EXPLAIN text has no schema; a wrong guess is worse than a flag |
| 2026-10-22 | "No dependents" views report partitioned tables at the parent-index level; attached partition indexes aren't listed on their own | Dropping the parent drops every partition index, so the parent must count as used when any partition index is; an attached partition index can't be dropped by itself, so listing it is noise |
| 2026-10-22 | SQL edition `index_no_dependents` returns nothing when plan_source = none | With no plan source nothing is known about any index; listing all of them read as "all safe to drop" |
| 2026-10-23 | `pg_index_query_stats` / `index_query_stats` find pg_stat_statements at query time (PL/pgSQL + dynamic SQL), not as a view dependency | Installs without pg_stat_statements, doesn't block dropping or moving it, and one text works across the PG 17 column rename |
| 2026-10-24 | SQL edition `index_drop_impact`: `p_timeout_ms` is a time budget for the whole call, not a per-EXPLAIN timeout | statement_timeout set inside a running statement doesn't re-arm the timer, so the old setting never stopped anything. A single EXPLAIN can't be interrupted from inside the function; for a hard limit set statement_timeout on the calling statement (safe now: the index is unhidden on cancel) |
| 2026-10-24 | SQL edition `index_no_dependents` leaves out every index on a table whose captured plans name an index that no longer exists | The plan text keeps the old name of a renamed index, and nothing says which current index it was. Holding back the table's indexes (verdict "unknown" in `index_usage`) is the safe side; it clears once the plan source is reset |
| 2026-10-24 | Report an index's role (primary key, unique/exclusion constraint, FK references, replica identity, ...) next to its queries, and a per-index verdict | "Unused" alone invited dropping indexes that enforce constraints or back foreign keys; the role says what else breaks |
| 2026-10-25 | Native: count in a backend-local table and flush to shared memory every `flush_interval` (default 1 s), at exit and before own reads | Benchmarks showed −3.4% on pgbench `-S`, from every statement writing the same shared lock and entry. Same model as PostgreSQL's cumulative statistics. Counts stay exact; other sessions see them up to 1 s late |
| 2026-10-26 | Native 0.8 records which index columns each query searched on (T07); goes beyond the PRD's "which queries use this index" | "Index (a, b, c) is only searched on a" is the next question after "who uses it", and the executed plan already has the answer for free (`indexqual` Vars). Native only: the SQL edition would have to parse `Index Cond:` text |
| 2026-10-26 | Pre-0.8 stats files are still read (T07 brief said: ignore them); their entries are flagged `columns_complete = false` | Ignoring the file would throw away every usage count on upgrade. The flag keeps the counts and makes the missing column history explicit, so an empty column set is never misread as "not searched" |
| 2026-10-26 | `pg_index_sole_path` ships as native 0.9 (T02 brief said 0.3), with an extra `other_indexes` column; top-level and nested calls of a query are merged; partition indexes fold into the parent, counted like `pg_index_dependents_rollup` (max per partition index) | The brief predates 0.3–0.8. `other_indexes` says what a `medium` query falls back to without a second query. Risk is about the query, not where it was called from. Folding matches how the index is dropped |
| 2026-10-25 | Native `sample_rate` scales counts by `rint(1/rate)` and flags sampling; while flagged, `pg_index_usage` reports "unknown" instead of "no recorded use" | A rarely used index can be missed by sampling; "safe to drop" must never come from an estimate |
